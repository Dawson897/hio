Jobs

Submit a job listing for editorial review. For advice on writing effective listings, see How your job postings can better attract the right candidates.

PUT|PATCH|DELETE https://api.reliefweb.int/v2/jobs/{uuid}?appname=REPLACE-WITH-APP-NAME

You need Access and credentials and Trusted URLs and UUIDs. For changes and withdrawals, see Update and Withdraw.

Field summary

Canonical schema: job.json. Field-by-field rules and examples: field reference.

Name Required Type Description
url yes string (IRI / URL) Immutable unique identifier in URL form under your trusted document prefix. Used to generate the job UUID. Does not need to resolve to a live page. Never change after first submission.
uuid yes string (UUID v5) Job UUID v5 computed as `uuid5(ReliefWeb namespace, url)`. Must match what the server computes from the exact url string.
title yes string Brief, specific job title. Prefer not to put location, salary, or other details in the title.
source yes array of integer Single source organization ID from /v2/sources (ReliefWeb integer taxonomy ID, not a UUID).
closing_date yes string (date-time) Application closing date-time (ISO 8601). Match your ad or careers portal.
body yes string (markdown or HTML) Full job description. Long enough to attract qualified candidates. Markdown or a small set of HTML tags.
how_to_apply yes string (markdown or HTML) Short application instructions only. Do not repeat the job description.
country no array of integer Country ID(s) from /v2/countries. Omit for remote, roster/roving, or location TBD.
job_type yes array of integer Single job-type ID from /v2/references/job-types.
job_experience yes array of integer Single job-experience ID from /v2/references/job-experience.
career_category yes array of integer Single career-category ID from /v2/references/career-categories.
theme no array of integer Single theme ID from /v2/references/themes. Choose only the most relevant.

Taxonomy fields are integer ids (source, job_type, job_experience, career_category, optional country / theme) â€” not UUIDs. Resolve them via the read API and /v2/references.
