Filter

Use filter to restrict which items are returned. Simple filters use field and value. Complex ones nest conditions with AND / OR.

Parameter specification

filter is an object with these keys:

Key Type Meaning
field string Field to filter on; see Resources
value boolean, integer, string, array, or object Match value(s). For dates/numbers, use { "from", "to" } (open-ended if only one bound). Omit value to test whether the field exists.
operator string AND or OR when combining array values or conditions
negate boolean When true, select items that do not match
conditions array Nest multiple filters

Filter by country

Return reports whose primary country is South Sudan (SSD):

POST

https://api.reliefweb.int/v2/reports?appname=REPLACE-WITH-APP-NAME

You can also filter on country.id, country.name, or primary_country.name. Discover IDs via /v2/countries or references.

Exact phrase matching

Filtering on a name field without quotes can match tokens separately. Quote the value and/or use a field marked exact in Resources.

Find the disaster named exactly Myanmar: Earthquake:

POST

https://api.reliefweb.int/v2/disasters?appname=REPLACE-WITH-APP-NAME

Date range

Return reports created in 2024:

POST

https://api.reliefweb.int/v2/reports?appname=REPLACE-WITH-APP-NAME

Use ISO 8601 dates. In GET URLs, encode + as %2B.

Combined conditions

Return Health-themed reports for Syria (SYR):

POST

https://api.reliefweb.int/v2/reports?appname=REPLACE-WITH-APP-NAME

Field exists

Omit value to select items where the field is present.

Return reports that have a headline:

POST

https://api.reliefweb.int/v2/reports?appname=REPLACE-WITH-APP-NAME

Negate

Return reports tagged France or Spain, but not Italy:

POST

https://api.reliefweb.int/v2/reports?appname=REPLACE-WITH-APP-NAME

Default filters (preset)

preset is a string. It applies bundled status filters and related defaults so you get the usual public listing behaviour without writing those filters by hand. It does not choose which fields appear in each result. That is profile and fields.

Exact status filters differ by resource. See each resource’s Defaults section under Resources.

Preset Use
minimal Default sensible status filters for most requests (hides expired jobs/training and archived disasters)
latest List-oriented sort (typically by date; countries and sources by id)
analysis Include archived disasters and expired jobs/training for historical analysis

Include expired jobs for trends:

POST

https://api.reliefweb.int/v2/jobs?appname=REPLACE-WITH-APP-NAME

Search for nutrition reports, newest first:

POST

https://api.reliefweb.int/v2/reports?appname=REPLACE-WITH-APP-NAME

With preset: "latest" and a query, results are sorted by date. With the default minimal preset and a query, results are typically ordered by relevance unless you set sort yourself.
